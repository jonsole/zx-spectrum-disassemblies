Sprites

Every sprite record, 78 of them end to end from SPRITE0 to the first instruction of the game at START. Each is drawn from its own bytes the way the drawing code (CALC_PIXEL_XY_AND_RENDER) reads them: a width byte (bits 0-3 the width in bytes), a height byte, then a mask byte and an image byte for each byte of each row, the bottom row first. Where the mask is set the background is cleared, and the image is laid in wherever it is set -- so an image bit shows whether or not the mask is set, a mask bit with no image is black, and where both are clear the background shows through (here, the blue-grey). This is Knight Lore's format (see Knight Lore's sprites).

Bits 6 and 7 of the width byte say whether the bytes are stored mirrored or upside down at the moment: VFLIP_SPRITE_DATA turns a sprite round in place, rewriting its bytes and toggling the bits, whenever it is drawn for an object facing the other way. On the tape every sprite is stored the right way round, with both bits clear, which is how they are drawn here.

Beside each are the graphic numbers that name it (a graphic is an object's first byte, looked up in GRAPHICS); see every graphic for what each is. One record no graphic number reaches: $88B3, which the game never draws. The first record, width and height both zero, is the empty sprite graphics 0 and 1 name; the drawing code sees the zero and draws nothing (FLIP_SPRITE).

The font

43 characters of 8 by 8 pixels at FONT, for the codes $30 to $5A: the digits, a second nought, a few signs and 3 blank characters ($3D, $3F, $40), and the capital letters. Each is eight bytes, the top row first, as the printer (PRINT_CHAR) copies them into the screen buffer. There is no lower case, and a space is printed as code $3D, the first of the blanks. For text the printer's base is 384 bytes below the font, so that the codes land on these characters; for numbers it is the font itself, so that the digits are codes 0 to 9. Drawn here in white; the game colours text by the attributes it prints with.

The character after the 9, code $3A -- a colon where the codes are ASCII -- is the same eight bytes as the 0 (compared at build time). It is there for the light-years clock (RUN_CLOCK): a digit that changes is printed rows out of line, the eight bytes from its character plus a count that runs down from 7 to 0 over seven turns (PRINT_ROLLING_DIGIT), so it rolls down into place from the digit above it like a counter's wheel. A 9 comes after a 0 -- a borrow -- and the character above the 9 is this second nought, so the 9 rolls in from a 0. Here is that roll, read from the font the way the clock reads it, count 7 first:
