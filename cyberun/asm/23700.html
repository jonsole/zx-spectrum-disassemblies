5C94: The things lying in the world: their kinds
The world's 290 objects -- the things lying in the landscape at fixed places, as opposed to the attackers -- are kept in three parallel tables: this one, one byte each; map_object_places, two bytes each (where); and map_objects_per_column, how many there are in each map column. They are in column order, so the objects of column C start at the sum of the counts of the columns before it (spawn_column_objects).
Each byte here: bits 0-5 the object's kind, 0-16, which spawn_objects_from_list copies into the object slot's +$13 and looks up in the table at object_kind_flags (bits 5-7 of that entry go into the slot's +$18, and with bit 4 set the slot's graphic is $1B instead of $0D, an animated object whose frame byte and frame range come from object_part_pairs); bit 7 set once player 1 has taken or destroyed the object, bit 6 once player 2 has (ship_hits_ground_objects and beam_hits_ground_object find the byte again from the slot's +$18 bit 0 and +$19, which hold its number), after which it never comes back for that player: play patches the BIT 7 in spawn_objects_from_list and the SET 7s in ship_hits_ground_objects and beam_hits_ground_object to bit 6 while player 2 plays. mask_world_objects ANDs every byte with a mask: $3F at a new game (new_game), so bits 6 and 7 are cleared and everything comes back; at the end of a planet (planet_secured) a mask from the player in play (player_in_play), $7F for player 1 and $BF for player 2, so that only that player's objects come back.
Read by spawn_column_objects and spawn_objects_from_list each time the screen moves to a new map column. Laid out below a line per map column, the kinds of that column's objects, from the game's bytes when the disassembly is built.
