61BC: The landscape map
The world: 96 columns by 28 rows of map cells, a byte each, a row after another (96 bytes a row). Each byte is the number of a tile, 0-$A9, which picks the tile's record through tile_table. A cell is a page the size of the play area; the view scrolls across the pages, so it straddles up to four of them, two across and two down, from the map position (a column and a row kept as a word by load_map_window) -- load_map_window collects their four tile numbers and draw_landscape draws them. Tiles turned upside down (see tile_records) give the caverns their ceilings.
map_cell_address finds a cell: row R (1-28) is at this table plus (R-1)*96. Row 0, the sky, is not stored: read_map_cell gives tile 0 for it. Below the last row load_map_window uses tile $20: for the lower cells when the map position is on row 28, and for all four when it is on row 29. Columns wrap: column -1 is 95 and column 96 is 0, so the world is a ring.
Tiles $00, $20, $2A and $A6 have no pieces, so a cell with one draws nothing: between them they fill most of the map. Laid out below a line per map row, from the game's bytes when the disassembly is built: rows 1-11 are the surface, in the planet's first colour, and rows 12-28 the caverns, in its second (set_landscape_colours).
