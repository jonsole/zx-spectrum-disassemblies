How the game is put together

Pentagram is Knight Lore's engine carrying a new game. The drawing, the depth sort, the collision code, the player's movement and much of the rest are Knight Lore's, sometimes to the instruction; the rooms, the quest and everything that moves or is fired or falls are new. This page is the map of the whole: where things are, what runs when, and which parts come from where. Knight Lore's own page describes the engine as it was.

Memory

The tape's one block of code and data loads at $5E00 and runs to $D89D; the loader enters it at its first byte, with the stack just below. Everything the game keeps is laid out from there up: the level data and the sprites first, then the variables and the object records -- all zero on the tape -- and the code. Above the code are the screen buffer, which every picture is drawn into before it is copied to the screen, and tables the game builds each time it starts. The system variables are not used and the ROM is never called -- its bytes are read only as random numbers -- since the game reads the keyboard and makes its sounds itself; and it runs with interrupts off, turning them on only while paused.

A game, a life, a room, a turn

START is four loops, one inside another. A game: the variables and records cleared, the drawing tables built, five lives, the menu, the start tune, the quest records set out afresh with the collectables put in five places chosen at random (NEW_QUEST), and one of four start rooms chosen (CHOOSE_START). A life: RESTART_PLAYER copies the player template over his two records and takes a life, and with none left it is the game over. A room: the quest things of the room he left are filed back in their records (QUEST_OUT_OF_ROOM), the room is built into the object records (ENTER_ROOM), the quest things that are in it are put in with it (QUEST_INTO_ROOM), the room is marked as one where things may or may not fall (BAN_DROPS), and the drop timer is set (RESET_DROP_TIMER). A turn: perhaps something falls (SKY_DROP), then every one of the 54 records has its update routine run, and OBJECT_DONE draws what changed and waits.

Walking through an arch jumps straight back to the room loop, dropping two return addresses from the stack by hand (EXIT_LOW_U); a death is noticed at the end of a turn, when both of his records have emptied, and goes back to the life loop.

The update routines

An object record's first byte is its graphic number, and that number is both what is drawn (through the graphic table, GRAPHICS) and what runs: UPDATES has a word per graphic, the routine the main loop jumps to with IX on the record and the address of OBJECT_DONE on the stack. So an object animates, or changes its behaviour, by changing its own first byte: the bolt steps through 151, 150 and 149, a quest item goes up by four when it is done, anything that dies becomes graphic 64, the puff, and then 1, which the drawing code empties. Most routines end the same way: set their own drawing offset, move through the collision code, and if anything moved, mark the object and what it overlaps to be drawn again (the end of HOMER). Scenery and anything else that never changes has NOTHING, a RET.

Speed

Every turn does the same work whatever is happening -- all 54 records are visited, empty or not -- and then OBJECT_DONE waits six units of about 33,000 T-states less the drawing the turn has done, so that a quiet room does not run faster than a busy one. A busy room, with six units of drawing or more, runs as fast as it can. Watched in the emulator, standing still for 50 turns: 123 frames in the empty room 30, with two units of waiting a turn, and 122 in the cluttered start room, with none.

Chance

RANDOM is one byte. It is stirred with the refresh register once before the menu, and after every object's turn with R, the turn counter and a byte of the ROM that the turn counter points at (OBJECT_DONE). Since R counts instructions, how long each update took feeds the next number. The start room, the collectables' places, what falls and where, and which way a spider turns all come from it.

The records went from Knight Lore's 40 to 54 and the code that walks them followed, but the list of what to draw did not: the bugs have what happens when room 87, the fullest, has a few things added to it. There is no day and night, no transformation, no cauldron and no clock.
