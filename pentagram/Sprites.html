Pentagram Sprites

Every sprite record, 89 of them end to end from SPRITE128 to the variables at CONTROL, with the font among them at FONT. Each is drawn from its own bytes the way the drawing code (DRAW_OBJECT) reads them: a width byte (bits 0-3 the width in bytes), a height byte, then a mask byte and an image byte for each byte of each row, the bottom row first. Where the mask is set the background is cleared, and the image is laid in wherever it is set -- so an image bit shows whether or not the mask is set, a mask bit with no image is black, and where both are clear the background shows through (here, the blue-grey). This is Knight Lore's format (see Knight Lore's sprites).

Bits 6 and 7 of the width byte say whether the bytes are stored mirrored or upside down at the moment: FIND_SPRITE turns a sprite round in place, rewriting its bytes and toggling the bits, whenever it is drawn for an object facing the other way. On the tape every sprite is stored the right way round, with both bits clear, which is how they are drawn here.

Beside each are the graphic numbers that name it (a graphic is an object's first byte, looked up in GRAPHICS); see every graphic for what each is. Sprites marked never drawn are named only by graphics nothing places, and 3 records no graphic number reaches at all.

The font

43 characters of 8 by 8 pixels at FONT, for the codes $30 to $5A: the digits; a full stop, a percent sign and a copyright sign; 4 blank characters ($3D, $3E, $3F, $40); and the capital letters. Each is eight bytes, the top row first, as the print routine (PRINT_CHAR) copies them into the screen buffer. There is no lower case, and a space is printed as code $3D, the first of the blanks. For text, the print routine's base is 384 bytes below the font, so that the codes land on these characters; for the score and the lives it is the font itself, so that the digits are codes 0 to 9. Drawn here in white; the game colours text by the attributes it prints with.
